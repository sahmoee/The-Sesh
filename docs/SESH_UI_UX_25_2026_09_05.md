# The Sesh — 25 journal, accessibility and recovery improvements

Implemented September 5, 2026. This is the UI half of the coordinated 50-change batch; networking, auth, persistence and service reliability are owned by the parallel core batch. Intake was clean. Existing palette, tab navigation, historical session meanings and private/local-authoritative save paths are retained. No commerce, consumption advice, dosing, medical claims, vendor or model changes.

## Remaining device QA / limitations

Source checks are not screenshots or end-to-end tests. Before publication, exercise a narrow iPhone, landscape, iPad full width and compact multitasking; light/dark themes; largest supported Dynamic Type; VoiceOver, Switch Control and keyboard dismissal. Check header placement, long custom tags, sheet scrolling and inline errors. Confirm cancellation/deletion on journal and stash rows, every editor's Back/swipe draft protection, all sort/filter combinations, locale decimals, editing a removed record, and repeatedly tapping Save.

Exercise chat offline, server backoff, queue capacity, disk-write failure, account switches and a normal successful send. Outbox status intentionally reveals no operation content, account identity or cross-account recovery choice; the root-owned outbox determines eligible retries. UI cannot guarantee disk durability of private journal CRUD while `AppSession` methods return no success/failure result; this batch does not change that persistence contract or claim otherwise. Private saving does not depend on optional community/music networking.

Ownership and compatibility: The Sesh client owns these presentation changes and the Foundation input policy. Shared controls are consumed by existing app views; no persisted model schema or Worker/public-site contract changes. Root's new outbox/send APIs must ship in the same app build as rows 24–25. Existing data needs no migration. Invalid newly entered numeric text remains editable; old records are not batch-rewritten. Draft protections are in-memory, not a promise of recovery after process termination. The current data model represents cost with the existing dollar convention; this task does not add currency conversion or commerce.
